# 存量系统说明（Brownfield 场景）

这是一个**刻意构造的存量系统样本**，用于演示《SDD 实战：规范驱动开发之道》
第 7.4 节"为存量系统补写规范"的完整流程。

## 它模拟的现状

对照书中 7.4.1 描述的存量系统四个特征：

| 特征 | 本样本中的体现 |
|---|---|
| **逻辑成谜** | 重试为什么是 3 次？超时为什么 30s？限流后为什么等 60s？代码里没有任何说明 |
| **需求散佚** | 没有 `proposal.md`，需求只存在于代码与口头约定中 |
| **架构漂移** | `GithubCollector.collect()` 既采集又拼文本；`ReportBuilder.build()` 生成完直接发邮件 —— 职责边界从未被定义过 |
| **测试薄弱** | 自动化测试覆盖率 0%，任何修改都伴随回归风险 |

此外还有两处典型的"隐性决策"（只在代码里、从未被记录）：
- `ReportBuilder.build()` 会对作者名做 `sorted()` 排序
- 提交信息超过 60 字符会被截断，单个成员最多列 200 条

## 注意

**不要模仿这里的写法。** 它的价值在于"反面样本" ——
`tools/brownfield.py` 的逆向工程分析器正是拿它来演示"隐性知识显性化"的。
