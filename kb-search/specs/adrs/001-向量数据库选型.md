# ADR-001：使用 Qdrant 作为向量数据库

## 状态
已采纳

## 背景
语义检索需要在数千到数十万级片段中做近邻搜索。需要选择向量库，
并确认它能在 Kubernetes 上以无状态服务形态部署、且支持按元数据过滤。

## 选项

| 选项 | 优点 | 缺点 |
|---|---|---|
| Qdrant | 原生支持元数据过滤与 payload；Rust 实现，单机性能好；提供官方 Python 客户端；可容器化部署 | 生态相对 Milvus 小；运维需额外组件 |
| Milvus | 生态成熟、支持十亿级规模、社区活跃 | 依赖 etcd/对象存储，组件重，本期数据量用不上 |
| Pinecone | 全托管、零运维 | 需外网访问与按量付费，数据出内网不合规 |

## 决策
使用 Qdrant

## 理由
1. `proposal.md` §2.3 要求部署在 Kubernetes 且服务无状态 —— Qdrant 可独立部署，
   搜索服务只通过 HTTP 访问它，自身不持有状态。
2. 本期数据量在万级片段，Qdrant 单机即可满足 §3.2 的 P95 < 500ms。
3. 需要按 `doc_id` 过滤与回溯来源，Qdrant 的 payload 机制可直接承载。
4. 不选 Milvus 是因为其 etcd + 对象存储的依赖对本期规模过重；
   不选 Pinecone 是因为数据不得出内网。
