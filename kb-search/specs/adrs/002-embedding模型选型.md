# ADR-002：使用 text-embedding-3-small 作为向量化模型

## 状态
已采纳

## 背景
需要把文档片段与用户查询编码到同一向量空间。模型选择直接影响检索质量、
调用成本与向量库存储量。

## 选项

| 选项 | 优点 | 缺点 |
|---|---|---|
| text-embedding-3-small | 1536 维，成本低，中文表现可接受，延迟低 | 语义精度弱于 large |
| text-embedding-3-large | 精度更高 | 维度 3072，成本与存储翻倍，延迟更高 |
| 自建 BGE 中文模型 | 中文专精、可离线、无调用成本 | 需 GPU 与运维，冷启动慢 |

## 决策
使用 text-embedding-3-small

## 理由
1. `proposal.md` §3.2 要求检索 P95 < 500ms —— 1536 维比 3072 维的检索与编码都更快。
2. 本期语料是团队内部技术文档，术语集中，`small` 的语义区分度已足够。
3. 成本敏感：同步 1000 篇文档会产生大量 token 消耗。
4. 自建模型需要 GPU 资源，与本项目"无状态、可水平扩容"的部署约束冲突。
5. 维度固定为 1536，作为契约写入 `design.md` §3，便于日后替换模型时评估迁移成本。
