# 知识库语义搜索工具

> 复现自《SDD 实战：规范驱动开发之道》第 1-2 章的案例项目。
> 第 1 章里它被小冰用 Claude Code 三天赶工、随后在 SDD 最小示例中被重新规范。

## 1. 背景与目标

### 1.1 背景
团队的核心知识散落在飞书文档中（技术方案、复盘、FAQ、规范），条目已有数千篇。
现有检索只能靠关键词精确匹配，同义表述（如"限流"/"rate limit"/"接口频率控制"）
往往搜不到，新成员查资料平均要翻 3~5 篇文档才能找到目标。

### 1.2 目标
基于语义向量检索，让用户用自然语言描述意图即可召回语义相关的飞书文档片段，
并返回可点击回原文档的结果，显著降低找资料的时间。

### 1.3 目标用户
- 主要用户（查询者）：研发团队成员，日均检索 3~10 次
- 次要用户（维护者）：负责同步飞书文档、观察检索质量

## 2. 功能范围

### 2.1 做什么（本期）

#### 文档接入
- 从飞书文档目录读取文档列表与正文
- 按固定长度切分为片段（chunk），保留来源文档 ID 与位置
- 对片段生成向量并写入向量库

#### 语义检索
- 接收自然语言查询，生成查询向量
- 在向量库中做近邻检索，返回 Top-K 片段
- 结果附带：文档标题、文档链接、片段原文、相似度分数

#### 接口
- 提供 `POST /search` 检索接口（JSON 输入输出）
- 提供 `POST /ingest` 触发一次文档同步（增量）

### 2.2 不做什么（本期明确排除）
- 不做大模型总结与问答（本期只做检索，不生成答案）
- 不做前端界面（复用现有前端，仅提供 API）
- 不做权限体系与用户体系（依赖调用方已有的网关鉴权）
- 不做多租户隔离
- 不做文档写入/编辑（只读飞书文档）

### 2.3 技术约束
- 开发语言：Python 3.11 及以上
- 向量库：Qdrant（见 ADR-001）
- 向量化模型：text-embedding-3-small（见 ADR-002）
- 部署：Kubernetes，搜索服务无状态、可水平扩容
- 外部依赖：飞书开放平台文档 API、Embedding 服务

## 3. 验收标准

### 3.1 功能验收
- [ ] 能按文档 ID 列表读取飞书文档正文并切分为片段
- [ ] 每个片段在向量库中可被检索到，且携带来源文档 ID 与标题
- [ ] `POST /search` 接受 query 与 top_k，返回不超过 top_k 条结果
- [ ] 返回结果按相似度降序排列，且包含相似度分数
- [ ] 检索到同一篇文档的多个片段时，结果可追溯到同一文档链接

### 3.2 性能验收
- [ ] 单次检索端到端耗时（不含网络往返）< 500ms（P95）
- [ ] 单次同步 1000 篇文档的耗时 < 10min
- [ ] 单篇文档读取失败不应阻断其余文档的同步

### 3.3 边界场景
- [ ] query 为空或全为空白字符时返回 400，不做检索
- [ ] top_k 超过上限（100）时按上限截断而不是报错
- [ ] 向量库为空时返回空结果列表，而不是抛异常
- [ ] 飞书文档正文为空时不写入空片段
- [ ] 单篇文档读取失败需在同步结果中标注该文档 ID，严禁静默跳过

## 4. 术语定义
| 术语 | 定义 |
|------|------|
| 文档 | 飞书知识库中的一篇文档（doc_id + 标题 + 正文） |
| 片段 | 文档按固定长度切分后的最小检索单元 |
| 向量 | 片段经 Embedding 模型编码得到的定长浮点数组 |
| 相似度 | 查询向量与片段向量的余弦相似度，取值 0~1 |
| Top-K | 检索返回的结果条数上限 |
| 同步 | 从飞书拉取文档、切分、向量化并写入向量库的完整过程 |
