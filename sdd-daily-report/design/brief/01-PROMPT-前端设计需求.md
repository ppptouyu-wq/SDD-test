# 设计需求：团队工作日报「本地只读展示页」

> 把本文件**全文**粘给 OpenDesign（连同 `02-数据契约.md`、`04-SAMPLE-REPORT.md`、`03-SAMPLE-REPORT.json`）。

---

## 一、一句话需求

给一个已有的 Python 命令行工具（每天自动生成团队工作日报、通过邮件和飞书机器人推送给团队 Leader）**补一个本地网页**，让 Leader 在浏览器里浏览历史日报，不用去翻邮箱。

## 二、这东西是什么 / 不是什么

**是什么**：一个**本地只读的浏览页**。跑在本机 `127.0.0.1` 上，读本地 SQLite 里的日报数据。

**明确不是什么**（请不要设计成这些，会偏离需求）：

- ❌ 不是 SaaS / 管理后台，**不做登录、不做用户管理、不做权限**
- ❌ **不做编辑功能**：日报不能改、不能删、不能手动补写
- ❌ **不做新增数据源配置页**（GitHub token / 飞书 key 都不在网页里填）
- ❌ **不做统计图表**（不做折线图、柱状图、团队成员活跃度排行）
- ❌ **不做暗色模式切换**（深色或浅色，你定一套就好）
- ❌ **不做移动端适配**（只在桌面浏览器看）
- ❌ **不做多团队/多租户切换**

原因：这个工具本身「不做智能摘要、不做统计分析、不做历史搜索」是已经写进需求文档里的边界，网页只是把已有的日报**展示**出来，不是扩展它的能力。

## 三、唯一的核心功能：浏览

就一条主线，做透：

```
日报列表（按日期倒序）
   ↓ 点某一天
日报详情（三段式 + 考勤）
```

### 3.1 日报列表

每条日报要能一眼看出：

- **日期**（如 `2026-08-20`）
- **团队名**（如 `平台研发组`）
- **生成时间**（如 `2026-09-27 01:27`）
- **本次日报里的成员有哪些**（列出名字）
- **数据健康度**：这次日报的采集是「全部正常」还是「有数据源失败」还是「全部失败」

> 数据健康度很重要 —— 这个工具有一条硬规则：**某个数据源挂了，必须在日报上显式标注「数据获取失败」，绝不静默跳过**。所以列表上要能一眼区分「这份日报是完整的」和「这份日报有缺失」。

### 3.2 日报详情

这是主页面，按下面顺序排：

**A. 抬头区**：日期 + 团队名 + 生成时间

**B. 总览表**：每个成员一行，四列 —— 成员 / 代码提交数 / 任务进展数 / 协作沟通数。要让人一眼看出「谁今天干了多少」。

**C. 成员分卡片**（每个成员一张，四段）：

| 段 | 内容 | 展示要点 |
|---|---|---|
| **代码提交** | 每条：仓库名、commit message、`+增/-删`、改动文件数、时间 | `+120/-18` 要**用颜色区分**（增加绿、删除红） |
| **任务进展** | 每条：任务标题、`状态A → 状态B`、时间 | 状态流转要**看得出方向**（箭头/标签） |
| **考勤** | 工时（如 `9.5h`）、状态（`正常`/`迟到`）、签到签退时间 | 状态要用**语义色**（正常=绿、迟到=橙/红）。**考勤取不到时，这一栏必须明确显示「考勤数据暂不可用」，不能空白、不能显示 0** |
| **协作沟通** | 每条：群名（如 `[平台研发组]`）、消息内容、时间 | 这是群里的原始讨论摘录，样式跟其他段区分开 |

**D. 空态**：某成员当天没有任何记录 → 对应板块显示 **「今日无记录」**（不是留白，也不是隐藏整块）

**E. 全局空态**：一条日报都没有 → 给一个明确的空页面提示

## 四、必须有的三个「特殊状态」

这三个状态是需求文档里的验收标准，请**一定设计出来**（不要只做理想态）：

1. **数据源失败**：某板块数据取不到 → 显式标注「数据获取失败」（例如某个成员的「代码提交」段写着"数据获取失败：GitHub API 限流"）
2. **考勤不可用**：整块显示「考勤数据暂不可用」
3. **今日无记录**：成员某板块当天为空

## 五、技术约束（重要，请务必遵守）

这套东西是给我**手工落地**到一个零依赖的 Python 项目里的，所以：

### 5.1 前端

- **纯 HTML + CSS + 原生 JavaScript**，**不要 React / Vue / Svelte / Next.js**
- **不要构建步骤**：不要 npm、不要 `webpack`/`vite`、不要 TypeScript 编译
- **单页面**（一个 `index.html` 可内联 CSS/JS），**不要多页路由 / History API**
- 可以用 **Tailwind CDN**；如果用了，请同时给出**等价的原生 CSS**（我的项目不能依赖 CDN）
- 数据通过 `fetch('/api/reports')` 和 `fetch('/api/reports/2026-08-20')` 取，**不要内联假数据当数据源**
- **界面文案全中文**

### 5.2 后端（我按你的设计稿实现，但请按这个形状来设计接口）

- Python **标准库 `http.server`**（不能引入 Flask/FastAPI/uvicorn）
- 只读：`GET /`、`GET /api/reports`、`GET /api/reports/{date}`
- 数据来自本地 SQLite，字段见 `02-数据契约.md`

## 六、需要你交付什么

1. **高保真原型**（HTML/CSS/JS，可直接在浏览器打开看效果）
2. **设计系统**：配色（给 hex）、字号阶梯、间距规范、圆角、阴影、语义色（成功/警告/危险/中性）
3. **组件清单**：列表项、成员卡片、数据行、状态徽章、空态、失败态 —— 每个组件给出 HTML 结构 + 用法说明
4. **对上面「四个状态」的视觉设计**：正常 / 数据源失败 / 考勤不可用 / 今日无记录
5. **截图**：列表页 1 张 + 详情页 1 张
