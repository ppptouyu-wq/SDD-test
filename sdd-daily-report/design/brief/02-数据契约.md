# 数据契约：日报的数据结构

页面上所有内容都来自这份数据。**请严格按照下面的字段设计页面，不要自行发明字段。**

---

## 1. 一份日报（日报详情页需要的数据）

```jsonc
{
  "date": "2026-08-20",              // 日报归属日期 YYYY-MM-DD
  "team_name": "平台研发组",          // 团队名
  "generated_at": "2026-09-27T01:27:02.587779",  // 实际生成时刻
  "members": [ /* 成员对象数组，见下 */ ],

  "markdown": "…",                   // 已渲染好的 Markdown 全文（服务端产出）
  "sources": {                       // 数据源健康度：决定「数据源失败」怎么显示
    "github": "ok",                  // ok | failed | skipped
    "lark_task": "ok",
    "lark_msg": "failed",
    "lark_attendance": "skipped"
  }
}
```

> `sources` 的三种值：
> - `ok` —— 采集成功
> - `failed` —— 采集失败（**页面上必须显式标注「数据获取失败」**）
> - `skipped` —— 本次未启用（如 mock 模式下的考勤）

## 2. 一个成员（成员卡片需要的数据）

```jsonc
{
  "name": "张三",                    // 显示名（可能被脱敏成「某成员」）
  "github_username": "alice",        // GitHub 用户名
  "commits":  [ /* 见 2.1 */ ],
  "tasks":    [ /* 见 2.2 */ ],
  "messages": [ /* 见 2.3 */ ],
  "attendance": { /* 见 2.4，可能为 null */ }
}
```

> **四个数组都可能为空** → 对应板块显示「今日无记录」。
> **`attendance` 可能为 `null`** → 显示「考勤数据暂不可用」。

### 2.1 `commits[]` —— 代码提交

```jsonc
{
  "repo": "example-org/example-repo",   // 仓库全名 owner/repo
  "message": "feat: 日报三段式编排",     // commit message（可能多行，取首行展示）
  "author": "alice",
  "timestamp": "2026-08-20T10:12:00+08:00",
  "additions": 120,                     // 新增行数
  "deletions": 18,                      // 删除行数
  "files_changed": 4                    // 改动文件数
}
```

展示要求：`+120/-18` 用颜色区分（加绿减红），并显示改了几个文件。

### 2.2 `tasks[]` —— 任务进展

```jsonc
{
  "title": "日报模板评审",
  "assignee": "alice@example.com",
  "status_from": "进行中",     // 变更前状态
  "status_to": "已完成",       // 变更后状态
  "updated_at": "2026-08-20T16:30:00+08:00"
}
```

展示要求：**状态流转要看得出方向** —— `进行中 → 已完成`。

### 2.3 `messages[]` —— 协作沟通

```jsonc
{
  "chat_name": "平台研发组",     // 群名
  "sender": "alice@example.com",
  "content": "项目日报的推送时间定在 18:00 可以吗？",
  "timestamp": "2026-08-20T15:20:00+08:00"
}
```

展示要求：这是群聊摘录，视觉上要和其他三段区分开（考虑用引用样式 / 气泡样式）。

### 2.4 `attendance` —— 考勤

```jsonc
{
  "employee_id": "alice@example.com",
  "date": "2026-08-20",
  "check_in":  "2026-08-20T09:32:00+08:00",
  "check_out": "2026-08-20T19:05:00+08:00",
  "work_hours": 9.5,          // 工时，小数
  "status": "正常"            // 正常 | 迟到 | 早退 | 缺卡 …
}
```

展示要求：`status` 用语义色（正常=绿，迟到/早退=警告色），并显示签到签退时刻。

## 3. 日报列表页需要的数据（列表项）

列表**不需要**完整的 members 数组，只要摘要：

```jsonc
{
  "date": "2026-08-20",
  "team_name": "平台研发组",
  "generated_at": "2026-09-27T01:27:02.587779",
  "member_names": ["张三", "李四"],   // 成员名列表
  "member_count": 2,
  "status": "ok"                     // ok | partial | failed —— 数据健康度
}
```

> `status` 三档：
> - `ok` —— 所有数据源正常
> - `partial` —— 部分数据源失败（**要在列表项上打标**）
> - `failed` —— 全部数据源失败

## 4. 接口形状（我按这个实现后端，请按这个设计前端）

| 方法 | 路径 | 返回 |
|---|---|---|
| `GET` | `/` | 页面本身 |
| `GET` | `/api/reports` | `[{列表项}, …]`，按日期倒序 |
| `GET` | `/api/reports/{date}` | 一份完整日报（第 1 节那个结构），找不到返回 404 |

## 5. 时间格式约定

- 日期：`YYYY-MM-DD`
- 时间戳：ISO 8601 带时区，如 `2026-08-20T10:12:00+08:00`
- 「生成时刻」：`2026-09-27T01:27:02.587779`（无时区，本机时区）
