# 交付物清单 & 你该往回拿什么

## 一、问 OpenDesign 要这 6 样（逐项对，缺了就补一句）

| # | 交付物 | 为什么必须要 | 我要拿它做什么 |
|---|---|---|---|
| 1 | **原型 HTML 文件**（最好一个自包含的 `index.html`，CSS/JS 内联） | 这是最终页面的样子 | 我照着它写零依赖实现 |
| 2 | **设计系统文档**：配色（**给 hex**）、字号阶梯、间距规范、圆角、阴影、语义色（成功/警告/危险/中性） | 没有具体色值我就只能凭感觉调，出来跟设计稿不一样 | 写进 `specs/design.md` 的 UI 一节 |
| 3 | **组件清单**：列表项 / 成员卡片 / 数据行 / 状态徽章 / 空态 / 失败态，每个给 HTML 结构 + 用法说明 | 页面是这些组件拼的 | 拆成实现任务 |
| 4 | **三种特殊状态的视觉稿**：数据源失败 / 考勤不可用 / 今日无记录 | 这是需求里的验收标准，容易只做理想态 | 逐条转成测试用例 |
| 5 | **截图**：列表页 + 详情页，各 1 张（PNG） | 给老师和你的 README 用 | 放进仓库 `docs/` 做设计留档 |
| 6 | **设计说明**：为什么这么排版、配色和字号怎么定的 | 体现"设计决策"，也是 SDD 要留的痕 | 写成 `ADR-004 前端设计选型` |

## 二、如果它只肯给一部分，按这个优先级砍

1. **原型 HTML**（最重要，没有它后面全都没法做）
2. **配色 hex**
3. **三种特殊状态的视觉**
4. 组件清单
5. 截图
6. 设计说明

## 三、拿到之后怎么给我

把 OpenDesign 的产出**统一放进一个 `output\` 目录**，然后告诉我"好了"。

建议结构：

```
opendesign_brief\output\
├── index.html              ← 原型
├── design-system.md        ← 设计系统（色值/字号/间距）
├── components.md           ← 组件清单
├── states.md               ← 三种特殊状态说明
├── design-notes.md         ← 设计说明
└── screenshots\
    ├── list.png
    └── detail.png
```

**如果它给的是代码片段而不是文件**，直接粘进一个 `.md` 文件丢进 `output\` 也行。

## 四、你只需要说一句"好了"，剩下的我来

我会按书里的 SDD 迭代闭环往下走：

```
① 改 specs/proposal.md   ← 加「本地 Web 展示页」，改 §2.2 边界
② 改 specs/design.md     ← 新增展示层模块职责 + 接口契约 + UI 设计（从你的设计系统来）
③ 写 specs/adrs/004-前端设计选型.md   ← 记录"为什么是这套设计/这个技术栈"
④ 改 specs/tasks.md      ← 加 Task 12
⑤ 写代码 web/            ← 按设计稿落地成零依赖实现
⑥ 每个验收标准转测试用例
⑦ python run_all_tests.py 全绿，治理检查通过
⑧ 演示给你看
```

## 五、先跟你交个底：哪些会跟设计稿不一样

| 设计稿里可能有的 | 我会怎么处理 | 原因 |
|---|---|---|
| Tailwind CDN | 换成等价原生 CSS | 项目不能依赖 CDN，要离线可跑 |
| 内联假数据 | 换成 `fetch('/api/reports')` | 数据必须来自真实 SQLite |
| 花哨动效 / 复杂交互 | 可能简化 | 新增依赖为零是硬约束 |
| 需要新依赖的功能 | 会跟你说，先不做 | 本机装不上 FastAPI/uvicorn |

**遇到这种偏差我会列给你看，不会自己闷头改。**
