设计说明

层级与信息架构：只做两级——列表页负责“哪几天有日报、状态如何”，详情页负责“每个人做了什么”。列表按日期倒序，日期是主键，所以用 18px 加粗数字 + 星期弱化注脚；团队名与元信息退到第二层，状态徽标靠右对齐形成可扫视的一列。

三种异常为什么长得不一样：数据获取失败是“系统出问题了”，用红色实心 chip（#cf1322 + #fff1f0 底 + ✕ 图标），最响；考勤数据暂不可用是“这一块缺失”，用虚线边框 + 琥珀色圆点的通知块，音量中等；今日无记录是“确实没有这件事”，只是静默的弱化文字，音量最低。红实心 / 虚线块 / 纯文字在形状、重量、色彩三个维度都不同，扫一眼即可区分。

品牌红与错误红：#d32029 是身份色，只出现在工具名的标记点和焦点环上，绝不用于表达失败；一切失败态统一用 #cf1322。两者色相接近，靠使用位置区分，避免“红色到底是品牌还是报错”的歧义。

状态不靠颜色单打：徽标 = 圆点色 + 文案，考勤状态 = 文字 + 颜色，图标 + 文字共同承担，色觉障碍用户也能读。正文 16px / 行高 1.52，弱化文字 #697386 仍保持 4.5:1 以上对比。

克制的原因：这是内部数据工具，不做图表、搜索、筛选、分页与编辑——读者只需要翻看，界面越安静，数据越突出。留白按 4/8 的节奏，容器 1200px、左右 36px，两列成员卡保证一屏内可横向对比。桌面单页、下限 1024px，不做移动端与暗色模式。
